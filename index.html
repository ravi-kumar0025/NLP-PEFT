The idea

PEFT freezes the pretrained model and trains under 1% of the parameters

A · Additive

Insert small new layers

  • Adapters (2019): within 0.4% of full FT on GLUE with 3.6% params
  • (IA)³ (2022): rescale activations, ~0.01% params

Extra layers add inference latency

B · Soft prompts

Learn vectors the model attends to

  • Prefix-Tuning (2021): every layer
  • Prompt Tuning (2021): input only

Weights untouched; costs context length

C · Reparameterized

Learn a low-rank weight update

  • LoRA (2021)
  • QLoRA (2023): LoRA on a 4-bit base
  • DoRA (2024): magnitude + direction

Merges into the weights: zero added latency

Our comparison: change the weights cheaply (LoRA, QLoRA) or leave them alone and change what attention sees (Prefix-Tuning).

PART

LoRA

Low-rank updates · rank r · zero-latency merge

ILoRA · Hu et al., 2021

LoRA learns the weight update as two thin matrices, B × A

h = W₀x + (α/r) · B A x
  • W₀ frozen; B is d×r, A is r×k, with r ≪ d, k
  • A random, B = 0: training starts at the pretrained model
  • Paper: attention Wq, Wv; modern practice: all linear layers
  • After training, merge W = W₀ + (α/r)BA: zero extra inference latency

Rank 1 is already competitive

With r = 1 on Wq and Wv, GPT-3 stayed competitive on WikiSQL and MultiNLI. The update a task needs has low intrinsic rank, which is why LoRA works.

What LoRA leaves on the table

The frozen base still sits in GPU memory at 16-bit: 14 GB for a 7B model, 130 GB for 65B. That is the next bottleneck.

Why it works

Pretrained weights are roughly zero-centred and normal. Equal-probability bins give each of the 16 codes an equal share of the weights.

NF4 beat FP4 and Int4 at 4 bits; with it QLoRA matched 16-bit LoRA on MMLU for 7B–65B LLaMA.

IIIdeas 02 and 03 · what they bought

With double quantization and paged optimizers, a 65B model trains on one 48 GB GPU

Double Quantization

One fp32 scale per block of 64 weights:

32 / 64 = 0.500 bits per weight

Quantize the scales to 8-bit, blocks of 256:

8/64 + 32/(64·256) = 0.127 bits

Saves 0.373 bits per parameter, about 3 GB on a 65B model

Paged optimizers

NVIDIA unified memory moves optimizer state to CPU RAM when a long batch spikes memory, then back. No out-of-memory crash.

Finding: adapt all linear layers

LoRA only on Wq, Wv fell short; LoRA on every linear layer matched full 16-bit fine-tuning.

PART

Prefix-Tuning

Virtual tokens · frozen weights · steering attention

IIIPrefix-Tuning · Li & Liang, 2021

Prefix-Tuning leaves every weight alone and learns virtual tokens each layer attends to

HOW IT WORKS · 4 STEPS
Attn(xWq, [PK; xWk], [PV; xWv])
  • 0.1% of parameters, ~250K per table-to-text task
  • Matched fine-tuning on table-to-text; beat it in low-data settings
  • Unstable alone: prefix made by an MLP, then the MLP is dropped
  • Mix prefixes from different tasks in one batch
  • Uses up context positions; adds attention cost

Prompt Tuning (Lester et al., 2021): vectors at the input only; matched full model tuning only at 11B parameters.

Takeaways

PEFT puts large-model fine-tuning on a student GPU

LoRA

Low-rank updates match full fine-tuning, train 10,000× fewer parameters and add zero inference latency. The default choice.

QLoRA

A 4-bit NF4 base with LoRA on all linear layers: 65B on one 48 GB GPU, 7B on a free Colab T4.

Prefix-Tuning

Smallest per-task storage and batchable across tasks, but less stable, costs context, and trails LoRA at scale.

Where the field went next

  • DoRA (2024): magnitude + direction, LoRA on the direction: +3.7 avg on LLaMA-7B commonsense reasoning over LoRA
  • (IA)³ / T-Few (2022): PEFT beat GPT-3 175B in-context learning (72.4% vs 66.6%) at ~1,000× lower inference compute
  • LoRA Without Regret (2025): LoRA on all layers matches full fine-tuning on small-to-medium datasets, at ~10× the learning rate
